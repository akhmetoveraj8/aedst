# ADR-0026: The gateway asks Go who a client is; the NATS envelope is Protobuf

- Status: Accepted (owner, 2026-11-28). Amends [ADR-0021](0021-nats-jetstream-and-rust-gateway.md)
  (its "Gateway", "Auth exception" and "Format" points). Keeps [ADR-0019](0019-remove-first-party-auth.md)
  intact: the server still issues no tokens. Applies [ADR-0025](0025-rust-admission-criteria.md) R4 and R5.
- Scope: `apps/server` (`internal/platform/realtime`, `internal/platform/natsbridge`, `internal/platform/auth`),
  `apps/gateway`. Spec: [`specs/realtime/ws-gateway.md`](../../specs/realtime/ws-gateway.md).

## Context

Two weaknesses of the Go/Rust split as ADR-0021 built it:

1. **Two OIDC verifiers.** The gateway verified access tokens itself (`jsonwebtoken`, its own JWKS cache,
   its own copy of `AEDST_OIDC_*` and of `ids.FromExternal`). Issuer, audience, algorithm list, token
   types, clock skew and the owner-id derivation had to stay identical in two languages, held together
   only by shared test vectors. A drift is an authentication bug.
2. **A JSON contract known only to fixtures.** The NATS body was a JSON shape defined by a Go struct and
   a hand-written Rust struct, pinned by `envelope.v1.json`. `buf breaking` could not see it.

A signed connect ticket issued by Go was considered for (1) and rejected: it is a second token format,
which ADR-0019 and `apps/server/AGENTS.md` forbid, and it brings signing keys, rotation and a client
round trip.

## Decision

### 1. Connection access: the gateway asks the Go server

- New service `aedst.realtime.v1.RealtimeService` (`api/proto/aedst/realtime/v1/realtime.proto`) with one
  RPC, `GetConnectionAccess` (no side effects, empty request). It returns the caller's owner id and the
  `exp` of the caller's access token. Handler: `internal/platform/realtime`. It reads only
  `auth.Identity` (which gained `ExpiresAt`, from the verified token's `exp`).
- Mounted through `modulekit.Mount` only when the NATS bridge is enabled (`AEDST_NATS_URL`). Any signed-in
  caller may call it and learns only about itself; a deployment can close it with `AEDST_ROLE_POLICY`.
  The per-user API rate limit applies.
- On every WebSocket upgrade the gateway calls it with the client's token as `Authorization: Bearer`,
  through the client generated by `connectrpc-build` (no hand-written Connect client). Answers:
  `unauthenticated` / `permission_denied` -> HTTP 401 to the client; `resource_exhausted` -> 429;
  anything else (Go down, timeout, incomplete answer) -> 503. Bound: `AEDST_GATEWAY_API_TIMEOUT_SECONDS`
  (default 3).
- The gateway forwards the client request's `X-Forwarded-For` unchanged: it is a transparent hop for the
  API. Otherwise every upgrade would reach Go from the gateway's address, and one client sending bad
  tokens would use up the per-address failed-authentication budget (`httpserver` `failureThrottle`) for
  everyone. This is correct when the same number of trusted proxies (`AEDST_TRUSTED_PROXY_HOPS`) stands in
  front of the gateway as in front of the API; a deployment that differs must align them.
- The gateway lost `AEDST_OIDC_*`, the JWKS cache, `jsonwebtoken`, `reqwest`, `sha2`, `uuid` and the
  owner-id mirror (`user_id_for`, `user_id_vectors.json`). It gained `AEDST_GATEWAY_API_URL` (plain
  `http://host[:port]`, the server inside the cluster).
- The client handshake is unchanged (`Authorization: Bearer`, or the `aedst.v1` + `aedst.bearer.<token>`
  subprotocols), and the socket is still closed at the token's expiry (4401).

### 2. The NATS body is `aedst.events.v1.EventEnvelope`

- New message in `api/proto/aedst/events/v1/envelope.proto`: `id`, `type`, `version`, `occurred_at`
  (`Timestamp`), `partition_key`, `payload` (bytes: the producer's JSON object, unchanged). The bridge
  publishes it in the binary encoding with `Content-Type: application/protobuf`.
- The gateway generates the type at build time from the same file (`build.rs`: `buf build` in
  `apps/server`, then `connectrpc-build`/`buffa`, as `apps/desktop` does). Nothing generated is committed.
- The **client frame does not change**: the gateway renders the same JSON text frame as before
  (`{id, type, version, occurred_at, partition_key, payload}`, payload inlined unchanged).
- Fixtures: `natsbridge/testdata/frame.v1.json` (the client frame, formerly `envelope.v1.json`) and
  `envelope.v1.binpb` (its Protobuf body, written by the Go test with `-update`). Go checks the body
  decodes to the event of the frame; Rust checks the body renders exactly the frame.

## Consequences

- One OIDC resource server again (Go). The "auth exception" of ADR-0021 is gone: no Go or Rust code
  outside `internal/platform/auth` verifies a JWT.
- The envelope is under `buf lint` and `buf breaking`; the Rust side fails to compile when a field it
  reads disappears.
- New sockets need the Go API: while it is down, upgrades answer 503 (open sockets stay). That costs
  nothing real, because a client that cannot reach the API cannot resync anyway.
- One extra internal request per upgrade. A reconnect wave after a gateway deploy is spread by the
  jittered `reconnect_after_ms` hint (0-5 s), and each request is one offline token check in Go.
- The gateway still uses plain HTTP to reach Go inside the cluster; TLS between them is the service
  mesh's job (no `client-tls`, no rustls roots in the gateway).

## Revisit when

Upgrades per second are high enough that the extra request shows in Go's latency or in the per-user rate
limit (then cache the answer per token hash until its `exp`, in the gateway, for at most a minute), the
gateway must reach Go across an untrusted network (then enable `client-tls`), or a second non-Go consumer
of events appears (it uses the same `EventEnvelope`).
