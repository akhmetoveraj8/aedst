# ADR-0001: Rust + Slint replaces Qt 6 / C++23 on Desktop

Status: Accepted (owner decision, 2026-11-01). The Qt tree has been deleted; this is the only Desktop app. Built and tested on Windows; never compiled on Linux. Sections below are a dated log; the update at the end supersedes earlier statements where they differ.

## Context

`apps/desktop` is a Qt 6.12 / C++23 app (about 45,000 lines in 28 modules) that was never configured or compiled. Its recorded costs were large: a hand-written Connect client (ADR-0001 of the old tree), a hand-written OIDC PKCE flow because QtNetworkAuth is GPL-only (ADR-0032), three secret-store providers (DPAPI, libsecret, key file), a custom update verifier, vcpkg + CMake + Qt Linguist tooling and a Qt LGPL compliance pipeline. The owner asked to move Desktop to Rust.

## Decision

- Language: **Rust** (edition 2024, toolchain pinned in `rust-toolchain.toml`), one Cargo workspace.
- UI: **Slint** 1.18.1 (declarative `.slint`, no WebView, native rendering). Chosen by the owner over Tauri 2, Iced, egui and cxx-qt.
- The Rust crates `connectrpc`, `openidconnect`, `keyring` and `velopack` replace code that the Qt app had to write by hand (see the table). Each is a registry-verified, maintained library, which is exactly the Library-First rule.
- Targets stay **Windows and Linux only** (macOS is `apps/apple`; the old ADR-0023 still applies).

## Directory strategy

The new app lives in `apps/desktop-rs` while the C++ tree stays untouched as the behavioural reference. At cutover (phase 9) `apps/desktop` is deleted and `apps/desktop-rs` is renamed to `apps/desktop`; every path in docs, Taskfile, CI and scripts is switched in that one change. Until then nothing may claim that the Rust app replaces the Qt app.

## Risks recorded (not hidden)

1. **Arabic / RTL.** Slint shapes RTL text, but layout mirroring is not automatic (an open feature request asks for reversible `HorizontalLayout`, `slint-ui/slint#13504`). Arabic is a required locale. Verify in a spike before porting any screen; if unacceptable, this decision must be revisited (Tauri 2 sharing `apps/web/shared` is the fallback). `UNVERIFIED`.
2. **Accessibility.** Slint's screen-reader support is narrower than Qt's. The old `Accessible.role/name` gate has no direct equivalent: check `accessible-role` / `accessible-label` coverage in a spike. `UNVERIFIED`.
3. **Slint licence.** Slint is `GPL-3.0-only OR Royalty-free-2.0 OR Software-3.0`. Desktop would ship under the Royalty-free licence, which carries attribution terms (an "About Slint" notice). Owner to confirm the terms are acceptable; recorded in `compliance` at the licence phase. `UNVERIFIED` until the licence text is read.
4. **MSRV.** Slint 1.18.1 needs Rust 1.92, `connectrpc` 0.9.1 needs 1.88. The `connectrpc` crate is pre-1.0 (0.9.x): pin exactly and re-run the conformance suite (which the old tree also never ran).
5. **Verification scope.** The toolchain is repaired and the spike builds on Windows only. Linux, packaging and everything beyond the spike remain unverified.
6. **Scale.** ~45,000 lines are ported, not translated mechanically; behaviour is taken from the C++ tests and `docs/contract/behavior/*.json` replay fixtures.

## Phase 3 results (contract and tokens, 2026-11-01)

- **`aedst-contract`**: `build.rs` runs `buf build --as-file-descriptor-set` in `apps/server` and passes it to `connectrpc-build`; the seven services the C++ app used (admin, auth, capabilities, media, notifications, search, tasks) generate messages and `*ServiceClient`s. Two integration tests pass (client construction, JSON round trip of an Arabic string). The Qt `methods.hpp` drift table is no longer needed: a new RPC appears when the proto changes.
- **Findings**: `connectrpc` generates messages with `buffa`, not `prost` (workspace corrected); `buffa-types` needs `json`; `buf --path` wants filesystem paths while `connectrpc-build` wants module names (hence the descriptor-set route); an RPC called `Register` does not compile because of open upstream issue connect-rust#309 (workaround in `build.rs`, documented); the default `zstd` feature pulled three RUSTSEC vulnerabilities flagged by `cargo deny`, so it is off (the client advertises gzip only).
- **Not verified**: a real call against a running server, the connectrpc conformance suite, per-method idempotency and retry policy (the protos do not declare it yet), streaming.
- **Tokens**: `packages/design-tokens` has a new `aedst/slint-globals` output. `crates/aedst-ui/ui/aedst_tokens.slint` is generated; the other platforms' outputs did not change. The pre-edit guard, the colour-literal check (now scans `.slint` and `.rs` under `apps/desktop-rs`) and the file-size config know the file.
- **`aedst-ui`**: `AedstLayout.rtl`, `AedstLabel`, `AedstButton` (keyboard, focus ring, `accessible-*`), `AedstActionRow` (primary action at the reading end), a `Gallery` window and `cargo run -p aedst-ui --example gallery -- [--rtl] [--dark]`. - **Leftover**: `crates/aedst-spike` is superseded by the gallery and should be deleted (the agent was not allowed to run a recursive delete).

## Phase 4 results (sign-in, 2026-11-01)

- **`aedst-oidc`**: `OidcConfig` (`AEDST_OIDC_*`), `Provider` discovery with the old checks (issuer, https, PKCE S256), `LoopbackListener` + pure `callback::parse_callback`, `RefreshTokenStore` (`KeychainStore` on `keyring`, `MemoryStore`), `OidcSession` (`restore`, `sign_in`, `access_token`, `refresh_after_rejection`, `sign_out`). The crate is about 1588 lines of source (unit tests included) plus its integration tests, against about 4,700 lines in the C++ `Core/Oidc`; `loopback.rs` and `session.rs` are a little over the 300-line guideline and should be split when they grow.
- **Better than the C++ plan**: the ID token signature is now verified (ADR-0025 skipped it); PKCE, state/nonce generation, code exchange and refresh are library code.
- **Tests**: 19 unit tests, 7 integration tests against a wiremock identity provider whose RSA key is generated at run time (no private key in the repository), and an `--ignored` round trip through the real Windows Credential Manager. Cases: PKCE and scopes on the wire, wrong nonce, no keychain, single-flight refresh with rotation, `invalid_grant`, unreachable provider keeps the session, sign-out.
- **Findings**: `IssuerUrl::from_url` appends `/` to a host-only issuer and the library compares byte for byte (fixed: the configured string is passed as is; ZITADEL issuers are host-only); `oauth2` refuses non-https revocation, so the revocation request itself cannot be tested against a plain-http fake (`SignOut.revocation` reports `Failed` there); the `rsa` crate carries RUSTSEC-2023-0071 (Marvin, no fix): ignored in `deny.toml` with a reason because production only verifies with public keys; `webpki-roots` needs `CDLA-Permissive-2.0` allowed.
- **Open**: a run against a real ZITADEL (random loopback port, JWT access tokens, scope names), Linux Secret Service, the revocation request over https, TLS roots (`openidconnect` bundles Mozilla roots; the transport policy of the Qt app used the OS store: switch to native roots or accept), the `SystemBrowser` path (never launched here), and wiring into the connect client (an interceptor that adds the bearer token and retries once after `unauthenticated`: phase 5).

## Phase 6 results (Tasks, the reference slice, 2026-11-01)

- **`aedst-feature-tasks`** with the layers of the recipe: `domain` (model, validation in code points, ports, `TaskService`), `data` (wire mapping, `ConnectTaskRepository`, outbox adapter and the two handlers `task.create`/`task.update`), `presentation` (`TaskListController`, plain `ListView` state), `ui/tasks.slint` and `ui_glue.rs` (the only Slint-aware Rust). The screen supports the list with paging, create with validation, complete/reopen, the pending badge, empty/error states, and the "waiting to sync" banner. The detail screen, edit, delete, search, stats and the due-date picker are NOT ported yet.
- **Behaviour kept from the spec**: the direct call is tried first with a fresh `Idempotency-Key` and only a retryable kind falls back to the outbox with the SAME key; unknown enums map to `Unknown` and are never offered in pickers; the page size is 20 with `created_at DESC`; `total_count` comes from the first page only; a stale response from an older load is dropped; `Cancelled` shows nothing; analytics carry the priority and a flag, never free text; the translated message is chosen by error KIND.
- **New shared pieces**: `ErrorKind` (13 kinds) in `aedst-common`, replayed against all 22 cases of `error-kinds.json`; `aedst-api::kind_of` (Connect code and `ErrorInfo` reason to kind, `unavailable` offline); `AedstTextField`, `AedstBadge`, `AedstCheckbox` and a `lib.slint` entry in `aedst-ui`.
- **i18n**: five catalogs (en, ru, tg, uz, ar) of 39 strings, bundled by `slint-build` and switched with `select_bundled_translation`. Findings: Slint looks translations up by `msgctxt` = component name, so the screen uses an empty context (`@tr("" => "...")`) and the catalogs carry no `msgctxt`; top-level functions do not exist in Slint (helpers live in the exported `TaskTexts` global); a property named `row` clashes with `Rectangle`; and `accessible-role: text` is read as a string when the component has a `text` property (use `AccessibleRole.text`). The ru/tg/uz/ar texts are machine-assisted and need native review. `tests/catalogs.rs` is the parity gate (no missing, stale, empty or placeholder-changed string).
- **RTL**: Slint does not reverse layouts, so the row, the priority bar and the header spell out both orders (`if AedstLayout.rtl`). Checked by snapshot on Windows in en (light), ar (RTL) and ru (dark, offline). `cargo run -p aedst-feature-tasks --example tasks_demo -- --lang ar --snapshot out.png` renders the screen with an in-memory repository.
- **Layer gate**: `tests/layers.rs` fails when `domain` imports data, UI or wire types, when `data` and `presentation` know each other, or when a feature depends on another feature.
- **Tests**: 106 in the workspace (39 new in the feature crate plus 3 in `aedst-common`, 3 in `aedst-api`).
- **Not done / open**: no real server run; the detail, edit and delete screens; due-date entry; the Slint snapshot depends on the window minimum size in this renderer (set `min-width/min-height`); keyboard and screen-reader behaviour of the new components is untested; `ErrorInfo` reasons are read from the JSON `debug` form only.
