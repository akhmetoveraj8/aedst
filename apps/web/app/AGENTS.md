## Rules that bite

- Validation boundary ([docs/content/web/validation.md](../../../docs/content/web/validation.md)): API-message forms use `protovalidateResolver` only (rules live in the `.proto`); Zod is for env/storage/non-proto input and never imported in `ui/**`; React Hook Form is state only (no `register(..., {rules})`, no `rules=`, every `useForm` has a `resolver`). Enforced by Biome plugins and `pnpm check:validation`.
- Tokens never reach page JavaScript: sessions are httpOnly cookies handled in `shared/lib/auth` and `src/proxy.ts`.
  Do not store tokens anywhere in the browser.
- Generated files are read-only: `shared/api/connect/generated/**` (`task app:generate`),
  `shared/ui/tokens.css` and `packages/design-tokens/dist/**` (`pnpm --dir packages/design-tokens build`),
  `next-env.d.ts`. A PreToolUse hook refuses edits to them.
- Biome is the only linter/formatter (no ESLint, Prettier). RxJS is rejected. `react-use` is not installed (hooks are hand-written exceptions listed in library-first/general.md).
- New dependency: if it is only planned, add it to `ignoreDependencies` in `knip.jsonc` (the allowlist; versions stay in `../pnpm-workspace.yaml`, never in `package.json`) and the Library-First page in the same change.
- Files stay at or under 300 lines (over 500 fails `task check:file-size`); one component per file; every file name is
  kebab-case (`task-form.tsx`), the exported component is PascalCase (`TaskForm`) (see conventions/web.md).

## Gates (run before saying done)

1. `task app:lint` (Biome + `tsc --noEmit`), `task app:knip`, `task app:test`. A change under `shared/` also needs `task web:lint web:test` (admin and landing use it).
2. `task check` (naming, file size, colors, i18n, boundaries, features) from the repo root.
3. A rule or script change: `pnpm check:selftest` (every gate must fail on its fixture in `lint/fixtures`). UI change: `pnpm test:stories` in `apps/web/app`, and `pnpm check:source` (no `ml-`/`pr-`/`left-`/`text-left` utilities, no Base64 images; exceptions only in `../shared/scripts/source-bans-allowlist.json`). Bundle impact: `task app:build` then `task app:check:bundle` (`../shared/scripts/check-bundle-size.mjs` against `bundle-budget.json`; a new route needs its own line, a removed route loses it).
4. `task app:lighthouse` after a build: `lighthouserc.json` holds the scores, Core Web Vitals, page weight, request count, font, stylesheet and image budgets and `server-response-time`. A session or cookie change: `shared/lib/auth/session-cookies.test.ts` keeps every cookie under 4096 bytes.
5. Claim only what ran. Playwright (`task app:test:e2e`) and Lighthouse need browsers and a production build. Budgets are ratchets: never raise one to pass.
