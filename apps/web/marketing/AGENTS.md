## Rules that bite

- Validation boundary ([docs/content/web/validation.md](../../../docs/content/web/validation.md)): API-message forms use `protovalidateResolver` only (rules live in the `.proto`); Zod is for env/storage/non-proto input and never imported in `ui/**`; React Hook Form is state only (no `register(..., {rules})`, no `rules=`, every `useForm` has a `resolver`). Enforced by Biome plugins and `pnpm check:validation`.
- Server Components by default. A new `"use client"` file needs a reason in its doc comment. Current islands: LocaleSwitcher (plain links; needs the current path), ErrorMessagesProvider and error.tsx. The FAQ is native `<details>`, the theme is one inline script (`providers/theme-script.tsx`), links are plain `<a>`: do not add `next/link`, `NextIntlClientProvider`, `next-themes` or a base-ui popup here without measuring `pnpm check:bundle` and `pnpm lighthouse`. A new kit import needs its file in the `@source` list of `styles/globals.css`.
- Pages must stay statically rendered: no `headers()`, `cookies()`, `searchParams`, no per-request nonce. Call `setRequestLocale(locale)` in every layout and page before `getTranslations`.
- No auth, session, ConnectRPC, `shared/api`, `shared/lib/auth`, PWA/service worker, PostHog or Sentry tracing here. No imports from `../app` or `../admin` (`@/shared/*` only).
- Arabic is RTL: logical CSS only (`ms-`, `ps-`, `start-`, `text-start`), never `ml-`/`left-`/`text-left`. `dir` and `lang` come from `shared/i18n/locales`.
- Every answer in the FAQ must be in the server HTML (JSON-LD `FAQPage` mirrors it); keep GEO content as real text, not images.
- Copy never invents facts: pricing, legal text and `siteConfig.organization.sameAs` are placeholders until the owner supplies real values.
- The site is a static export (`output: "export"`, [marketing-static](../../../docs/content/web/marketing-static.md)): no proxy, `headers()`, redirects, rewrites or Server Actions. The CSP is `script-src 'self'` plus one SHA-256 per inline script, generated after the build by `scripts/build-security-headers.mjs` (policy in `scripts/security-policy.mjs`); never `'unsafe-inline'`, never hand-copied hashes. A metadata route exports `dynamic = "force-static"`, a dynamic route has `generateStaticParams`.
- Biome only; no color literals (design tokens); no raw `<button> <input> <form>`; files at most 300 lines.
- Budgets are ratchets: `bundle-budget.json` and `lighthouserc.json` (performance >= 0.95) must not be raised to pass.

## Gates (run before saying done)

1. `pnpm --filter @aedst/web-marketing lint typecheck test knip` (or the matching `task web:*` once wired), then in `apps/web/marketing`: `pnpm check:feature-boundaries` (authoritative) and `pnpm check:deps`.
2. `pnpm check:source` (no `ml-`/`pr-`/`left-`/`text-left` utilities, no Base64 images), `pnpm check:dates` (sitemap `lastModified` is a real past date and matches the legal pages' "Last updated" line in all five locales) and `pnpm check:selftest` (negative fixtures of the shared gates). Then `pnpm build`, `pnpm check:bundle` (`bundle-budget.json`; a new route needs its own `shell` line), `pnpm test:e2e` (`pnpm test:a11y` runs only the axe spec; Playwright on the built site served by `scripts/serve-out.mjs` with its generated headers: `e2e/csp.spec.ts` checks the hash-only CSP, zero violations, the locale redirect of `/` and the localized 404, `e2e/seo.spec.ts` checks canonical, hreflang with x-default, `og:url`, JSON-LD types and one `h1` on every page in all five locales, `e2e/accessibility.spec.ts` runs axe at WCAG 2.2 AA including right-to-left; a new page goes into `e2e/support/pages.ts`) and `pnpm lighthouse` (`lighthouserc.json`). The release image sets `AEDST_REQUIRE_REAL_SEO=1`, which makes `prebuild` refuse placeholder copy and a localhost site URL; `pnpm check:seo` runs that guard on demand (it fails while the template copy is in place).
3. `pnpm check` runs the same gate set as `app` (plus `check:dates`); the scripts are shared from `../app/scripts` with `AEDST_WEB_ROOT=.`.
4. `task check` from the repo root (naming, file size, colors, i18n, boundaries).
5. View `/en`, `/ar` (RTL) and `/robots.txt`, `/sitemap.xml`, `/llms.txt` in the running site.
