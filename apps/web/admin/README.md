# apps/web/admin

The AEDST admin panel: a React single-page app (`@aedst/web-admin`) built by Vite with TanStack Router, served as static
files (`dist/`) by a small Hono BFF (`server/`) on its own domain (for example `admin.<domain>`), next to the product app
(`../app`) and the marketing site (`../landing`). It shares only the source-only kit in `../shared` (UI, generated Connect
clients, auth helpers, i18n).

- URLs: `/{locale}/admin`, `/tasks`, `/broadcast`, `/audit` (en, ru, tj, uz, ar). `/` and a path without a known locale
  redirect (client-side) to the negotiated locale; `/{locale}` redirects to `/{locale}/admin`. `ar` sets `dir="rtl"`.
- The SPA never sees tokens. The BFF owns the OIDC flow and the httpOnly `__Host-` cookies:
  - `GET /api/auth/session` -> `200 {"authenticated":true,"email","name"?,"sub"?,"roles":[]}` or `401` (probed once, in the root route);
  - sign-in is a full-page navigation to `/api/auth/login?next=<relative path>`;
  - sign-out is `POST /api/auth/logout` -> `{"endSessionUrl": string | null}` (see `../shared/lib/auth/logout.ts`);
  - RPC goes to the same-origin `/api/rpc`; `GET /api/healthz` is the BFF's.
- Route guards (`beforeLoad`) are cosmetic: anonymous -> sign-in, no operator role -> `/{locale}/forbidden`, missing
  permission -> forbidden. The BFF guards the HTML and apps/server's RoleInterceptor guards every RPC.
- Never indexed, no PWA, no PostHog, no consent banner.

## Layout

| Path                          | What                                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `index.html`, `src/main.tsx`  | Entry. `index.html` carries the `__CSP_NONCE__` placeholder (`vite.config.ts` `html.cspNonce`) |
| `src/app/routes/`             | File-based routes (`__root`, `$locale/route`, `$locale/admin/...`); code-split per route       |
| `src/app/routeTree.gen.ts`    | Generated by `@tanstack/router-plugin` on every `vite dev/build`. Committed, never hand-edited |
| `src/app/i18n/navigation.tsx` | Admin-only `@/shared/i18n/navigation` (Link, usePathname, useRouter, redirect), aliased        |
| `src/app/auth/`               | Session probe (`session.ts`) and cosmetic guards (`guards.ts`)                                 |
| `src/app/config/`             | env, Sentry, i18n catalogue loader (`import.meta.glob`), search-param schemas                  |
| `src/modules/admin/`          | The feature module (reference): UI, i18n JSON, manifest                                        |
| `vite.aliases.ts`             | Aliases shared by Vite and Vitest (`@/shared/*`, navigation seam, `@sentry/nextjs` -> react)   |

## Run

```
cp .env.example .env.local
pnpm dev          # Vite on http://localhost:3001, proxies /api/** to ADMIN_BFF_URL (default http://localhost:3101)
pnpm build        # static files in dist/
pnpm test && pnpm lint && pnpm typecheck && pnpm knip && pnpm check:deps
```

Generated Connect clients come from `pnpm --filter @aedst/web-app connect:generate` (they land in `../shared/api/connect/generated`).
Rules for contributors and AI agents: [AGENTS.md](AGENTS.md).

## Environment

Browser variables use the `VITE_` prefix and are inlined at build time (never put a secret in one). The shared kit
(`../shared/env/client.ts`) is the single validated source for the shared ones; `vite.config.ts` maps `VITE_<NAME>` onto its
`process.env.NEXT_PUBLIC_<NAME>`. Admin-only ones are validated in `src/app/config/env.ts`.

| Variable                                                                       | Where read           | Meaning                                                       |
| ------------------------------------------------------------------------------ | -------------------- | ------------------------------------------------------------- |
| `VITE_SITE_URL`                                                                | shared kit           | Canonical origin of this project                              |
| `VITE_APP_URL`                                                                 | `src/app/config/env` | Origin of `apps/web/app` for the "back to app" link           |
| `VITE_SENTRY_DSN`, `VITE_SENTRY_ENVIRONMENT`, `VITE_SENTRY_TRACES_SAMPLE_RATE` | shared kit           | Sentry browser SDK (inert without a DSN)                      |
| `VITE_SENTRY_RELEASE`                                                          | `src/app/config/env` | Release name when the Vite Sentry plugin does not inject one  |
| `ADMIN_BFF_URL`                                                                | `vite.config.ts`     | Dev proxy target for `/api/**`                                |
| `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, `SENTRY_PROJECT`, `SENTRY_RELEASE`          | `vite.config.ts`     | Source-map upload during `vite build` (skipped without token) |

The BFF reads its own variables (`API_BASE_URL`, `OIDC_*`, `AUTH_COOKIE_NAME`, `AUTH_ROLES_*`, ...) and documents them in `server/`;
the SPA reads none of them.
