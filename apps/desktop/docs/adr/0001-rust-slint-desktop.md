# ADR-0001: Rust + Slint for Desktop

Status: Accepted (owner decision, 2026-11-01). Desktop is frozen like the other non-Core platforms: it passes `cargo fmt`,
`clippy -D warnings`, `cargo test` and `cargo deny` on Windows only and was never compiled on Linux. Current evidence lives in
[status](../../../../docs/content/status.md), not here.

## Context

The Desktop client (Windows and Linux; macOS is `apps/apple`) must reach parity with the other clients on sign-in, offline
writes, capabilities, five locales including Arabic (RTL), signed self-updates and consent-gated telemetry. The Library-First
rule asks for maintained libraries for each of those, and the repository wants as few toolchains as possible: one language for
the whole Desktop app, one package manager, one lint and test story, and generated (never hand-mirrored) RPC types.

## Decision

- Language: **Rust** (edition 2024, toolchain pinned in `apps/desktop/rust-toolchain.toml`), one Cargo workspace of small
  `aedst-*` crates; every dependency is declared once under `[workspace.dependencies]` (versions: `apps/desktop/Cargo.toml`).
- UI: **Slint** (declarative `.slint`, native rendering, no WebView). Tauri 2, Iced, egui and Dioxus were offered and not chosen.
- Library-First crates instead of hand-written infrastructure:

| Concern | Crate(s) | Notes |
|---|---|---|
| RPC | `connectrpc` + `connectrpc-build` (messages by `buffa`) in `aedst-contract` | Types are generated from the server's `buf` descriptor set at build time; nothing generated is committed. `zstd` is off (advisories); the client advertises gzip |
| Sign-in | `openidconnect` (Authorization Code + PKCE S256) + a `tokio` loopback listener, in `aedst-oidc` | ID token signature is verified; refresh token in the OS keychain. A core crate, not a feature |
| Secrets | `keyring-core` + the Windows and Secret Service stores; `aes-gcm` for data at rest | No file fallback |
| Persistence | `rusqlite` on one dedicated thread, `PRAGMA user_version`, migrations frozen by hash (`aedst-persistence`) | Custom migrator because `rusqlite_migration` pins an older `rusqlite` |
| Offline writes | `aedst-outbox` on `tokio`, one `Idempotency-Key` per item | Project-specific domain logic |
| Updates | `velopack` + an Ed25519-signed manifest (`aedst-update`, `aedst-release`) | The feed is not trusted; the manifest binds version, SHA-256 and size |
| Telemetry | `tracing` + `tracing-subscriber` + `tracing-appender`; `sentry` (consent-gated) in `aedst-telemetry` | One PII scrubber; analytics go to the project's own server |
| UI kit and tokens | `aedst-ui` (`.slint`), tokens generated by Style Dictionary (`aedst/slint-globals` output) | No colour literals in hand-written `.slint` |
| Navigation, capabilities | `aedst-navigation`, `aedst-capabilities` | Features are static crates; there is no run-time plugin loading |
| Features | one crate per feature (`aedst-feature-*`) with `domain`, `data`, `presentation` and a `.slint` view bound in `ui_glue.rs` | Reference slice: `aedst-feature-tasks`. Domain is pure; features depend on core crates only |
| i18n | Slint `@tr()` with gettext `.po` catalogs for en, ru, tg, uz, ar | `tests/catalogs.rs` per crate is the parity gate |
| Quality | `rustfmt`, `cargo clippy -D warnings`, `cargo-deny`, `cargo nextest`, `proptest`, `insta`, `wiremock`, `mockall`, `i-slint-backend-testing` | `unwrap()` and `unsafe` are forbidden in hand-written code |

## Known costs and risks

1. **RTL.** Slint shapes Arabic text and bidi correctly but does not mirror layouts or alignment. Mirroring is centralised in
   `aedst-ui` (`AedstLayout.rtl`, reading-order-aware components) so features never do it themselves; screens that lay out
   rows directly spell out both orders. If this becomes unmanageable, revisit this decision.
2. **Accessibility.** UI Automation on Windows exposes text, edits and buttons with their `accessible-label`. Linux (AT-SPI)
   and a real screen-reader pass (Narrator, NVDA, Orca) are UNVERIFIED.
3. **Licence.** Slint ships under its Royalty-free licence, which requires an attribution notice; `deny.toml` accepts it.
   Some transitive crates behind Slint are flagged unmaintained (no vulnerability): re-check on every Slint bump.
4. **Pre-1.0 crates.** `connectrpc` is 0.9.x: pinned with `=`, and the Connect conformance suite has not run yet.
5. **Video.** Slint has no built-in video player; the Media feature previews images only.
6. **Slint specifics.** Generated code needs `mod generated { slint::include_modules!(); }` with lints relaxed inside it only;
   translations are looked up by `msgctxt` = component name, so screens use an empty context; each feature crate compiles its
   own `.slint`, and the shell's `build.rs` embeds the feature `ui_glue.rs` files and merges their catalogs.

## Consequences

- Desktop gates are Rust gates: `task desktop:{fmt,lint,test,build,deny}`, `task verify:desktop`, the crate boundary and
  approved-crate scripts in `apps/desktop/scripts/`, and `.github/workflows/desktop-ci.yml` (not yet green on GitHub).
- A dependency is added through `apps/desktop/approved-crates.txt` and [library-first/desktop](../../../../docs/content/library-first/desktop.md) in the same change.
- Desktop is frozen: no new features until Core (Server + Web) is green for that feature and Desktop has one green CI run
  ([rules](../../../../docs/agent/rules.md#core-first)).

## Revisit when

- RTL mirroring or a screen-reader pass cannot be made acceptable inside `aedst-ui`.
- Slint's licence terms change, or Slint stops being maintained.
