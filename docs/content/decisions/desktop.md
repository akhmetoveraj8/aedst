# Decisions: Desktop (Rust + Slint; built on Windows only)

Part of the [decisions index](/decisions). Status and verification legends are defined there.

> **2026-11-01: Desktop is Rust + Slint** (owner decision, [ADR-0001](../../../apps/desktop/docs/adr/0001-rust-slint-desktop.md)). `apps/desktop` is the only Desktop app. Status of every row: built and tested on Windows, never compiled on Linux, never run against a real server or identity provider, unless a row says otherwise.

| Decision | Status | Rationale | Revisit when |
|---|---|---|---|
| Rust (edition 2024) + **Slint 1.19.1**, one Cargo workspace; Tauri 2 and Iced/egui/Dioxus were offered and not chosen; no other language or UI toolkit, no FFI UI bindings. Windows and Linux only (macOS is `apps/apple`) | Accepted (owner); Windows verified | Slint is native, declarative, no WebView | A screen-reader pass or the Linux accessibility check fails; then fall back to Tauri 2 sharing `apps/web/shared` |
| `connectrpc` (pinned exactly `=0.9.1`, pre-1.0), `openidconnect` 4.1.0, `keyring-core` + chosen stores, `velopack` + `ed25519-dalek` replace hand-written client, PKCE flow, secret providers and update transport; contract codegen via `buf build` in `apps/server` + `connectrpc-build` (messages by `buffa`), `zstd` off (RUSTSEC-2026-0391/0398/0403), nothing generated is committed | Accepted; registry-verified 2026-11-04 | Library-First | A `connectrpc` conformance run fails (suite still **Pending**), or a crate is unmaintained |
| Design tokens reach Slint through the Style Dictionary output `aedst/slint-globals`; RTL mirroring is centralised in `aedst-ui` (`AedstLayout.rtl`) because Slint does not mirror layouts | Accepted; checked by screenshot on Windows (LTR, RTL, dark) | ADR-0001 spike | Slint gains layout direction support (slint-ui/slint#13504) |
| **Sign-in is OIDC Authorization Code + PKCE only** (`openidconnect` + loopback + system browser). No email/password UI, use case, strings or `AuthService` client: the first-party auth proto was removed from the server and `aedst-contract` no longer generates it (the connect-rust#309 `Register` workaround is deleted with it). Only the refresh token and subject persist, no file fallback; `invalid_grant` ends the session, network failures keep it | Accepted; Windows only; sign-in screen states covered by UI tests | Implements server ADR-0001 for Desktop | A run against real ZITADEL shows random loopback ports or scopes need changes; Linux Secret Service untested |
| **Secrets use `keyring-core` with explicitly built stores** (`windows-native-keyring-store` 1.1.0, `zbus-secret-service-keyring-store` 1.0.1) instead of the `keyring` 4.2.0 meta crate; no global default store; mock store in tests; the meta crate is denied in `deny.toml` | Accepted 2026-11-04; mock-store tests; Linux store compile-checked only if CI runs it (**UNVERIFIED**) | The `keyring` docs advise applications to take `keyring-core` plus the stores they use; the entry layout is unchanged, so stored sessions survive | A store crate becomes unmaintained, or macOS is ever added |
| **SQLite migrations stay a custom list** (about 40 lines, frozen by SHA-256, newer file refused). `rusqlite_migration` 2.6.0 was evaluated: maintained, Apache-2.0, MSRV 1.95, but it requires `rusqlite ^0.40` while the workspace is on 0.41.1 and it has no hash freeze | Accepted (rejected library) 2026-11-04 | One `libsqlite3-sys` can link only once | `rusqlite_migration` supports the current `rusqlite` (then adopt it and keep the freeze as a test) |
| **Product analytics goes through the project's own Go server**, one consent point for all clients; `posthog-rs` and `AEDST_POSTHOG_*` are removed. `apps/server` has no analytics/ingest RPC (checked 2026-11-04: no proto or module), so Desktop ships the port (`AnalyticsSink`, `EventTransport`), the contract allow-list, consent gating and an in-memory bounded `BufferedTransport`; the Privacy switch is disabled (`analytics_available = false`) so nobody consents to something that does not leave the device. Sentry stays consent-gated and separate | Accepted; **follow-up Pending: the server ingest RPC** (owned by the server agent/owner, not edited here) and a Desktop adapter that posts to it | Same consent model as the other clients; no third-party SDK or origin | The server adds an ingest RPC: write the adapter behind `EventTransport`, flip `ANALYTICS_INGEST_AVAILABLE` |
| **UI tests use `i-slint-backend-testing` `=1.19.1`** (internal Slint crate: pin with `=`, bump with `slint`). First tests: `AedstButton` keyboard activation (Space, Enter, accessibility action), `AedstActionRow` order and edge in LTR and RTL, keyboard order in RTL, gallery smoke in four modes, and the sign-in screen states in `aedst-desktop` | Accepted 2026-11-04 | Headless, no GPU | Slint publishes a supported public testing API |
| `aedst-spike` is removed; the gallery replaces it | Done 2026-11-28: the crate and the `exclude` entry are deleted | Throw-away spike, superseded | n/a |
| **Crate boundaries are a script, not a cargo test** (2026-11-21): `scripts/check-feature-boundaries.sh` (bash + node) enforces D1-D6: no feature to feature, features use only `aedst-api`, `aedst-common`, `aedst-contract`, `aedst-outbox` (tests also `aedst-persistence`), only `aedst-desktop` composes features, no `std-widgets` in a feature, flat-or-split layout. The allowlist is the graph of that day, not a design | Accepted; script and negative self-test pass; nothing compiled | The gate must run where there is no Rust toolchain (this machine, `policies-ci`); `tests/layers.rs` needs cargo | A feature needs `aedst-navigation`, `aedst-capabilities` or `aedst-telemetry` directly: extend the list in the script and in [desktop/boundaries](/desktop/boundaries) |
| **Feature level inside a crate** (owner decision "module, then feature"): `src/<feature>/{domain,data,presentation}` + `ui/<feature>/`, shared code in `src/shared` and `ui/shared`, one catalogue per crate; a one-capability crate stays flat; never mixed (rule D6) | Rule and gate accepted 2026-11-21; **no crate split yet** (all five are flat) | Same shape as the other platforms; a split without a compiler is not mechanical (`ui_glue.rs` is compiled twice, `tests/layers.rs` paths move) | After the first green CI run: split `notifications`, `admin`, `media` |
| **Approved direct dependencies are a list file checked by a script**: `approved-crates.txt` next to `deny.toml` (Desktop and gateway), `scripts/rust/check-approved-crates.sh` (A1-A4). cargo-deny 0.20.2 `[bans] allow` covers transitive crates too, so it cannot hold the list; `[bans.workspace-dependencies]` (`duplicates = "deny"`, `unused = "warn"`) was added and never evaluated | Accepted 2026-11-21; script passes; cargo-deny part **UNVERIFIED** | Makes the `Cargo.toml` claim "a crate may be used only after it is approved" true without cargo | cargo-deny gains an allow-list for direct dependencies |
| **Desktop and gateway stay two Cargo workspaces with identical shared versions**: the script fails on version drift (V1), lint-level drift (L1) and toolchain drift (T1). `clippy::expect_used` raised to `deny` on Desktop to match the gateway (CI already denied warnings). Not aligned: `clippy::panic` (gateway only), `unsafe_code` (`deny` here, `forbid` there, Slint), `rust-version` (1.95 here, 1.100 there) | Accepted 2026-11-21; no drift found (12 shared crates); lock files not regenerated | Merging workspaces needs a lock-file regeneration, impossible without cargo | A compiler shows `clippy::panic` passes on Desktop; then deny it and drop the exception |
| Core services: `aedst-persistence` (one DB thread, hash-frozen migrations, `kv`), `aedst-outbox`, `aedst-capabilities`, `aedst-navigation`, `aedst-api`. Schema starts at version 1. No run-time plugins: features are static crates. Behaviour is pinned by the shared fixtures `offline-outbox.json`, `capabilities.json`, `session-refresh.json`, `error-kinds.json` | Accepted; Windows only | Library-First; `connectrpc` has no client interceptors, so the bearer goes through `CallOptions` | No real server run; no connectivity monitor (the host must trigger the outbox and capabilities refresh); `upgrade_required` from `ErrorInfo` details is not parsed |
| Features Search, Notifications, Admin, Media on the Tasks pattern from one brief; writes are never queued offline except Tasks; screens render kind-translated errors | Accepted; each crate's gates pass on Windows | Library-First: `reqwest` only for the presigned object-store transfer | Native file picker, toasts, thumbnails, video, plural forms, a shared-strings catalog |
| Shell: ONE Slint compilation for the window and the five views; each feature's `ui_glue_body.rs` is included into the shell's `glue` module (see "Feature glue by `include!`"); feature catalogs merged into one per language by context; API client uses the OS trust store | Accepted; compiles, opens, shows login and each section in debug captures | Library-First | A privacy settings screen wired to a real ingest; ID-token roles for the Admin gate |
| **Session scope** (2026-11-28): per-user controllers and session work (outbox delivery, unread poller, "waiting to sync" counter) live in `SessionScope` (`aedst-desktop/src/session.rs`); a fresh scope is bound at start and after every sign-out and started at sign-in; every glue `bind` returns the abort handles of its forwarding tasks and the scope aborts them when it ends, so an old controller never writes into the window again; queued writes carry an owner (`outbox.owner`): sign-in drops another account's writes before anything is delivered, sign-out drops them before the network revoke; app-wide services stay in `Services` | Accepted; **written, not compiled** (no cargo on the authoring machine) | Sign-out used to leave the previous user's lists in memory and the chores running; a scope ends both structurally | A second window or multi-account support |
| **One feature table** (2026-11-28): `features.rs` (`FEATURES`) derives sections, routes, link prefixes, capability flags and the client build; `feature_ids.rs` is the one list, included by `build.rs` and checked by a test | Accepted; not compiled | Adding a feature touched about nine places | Run-time feature discovery (none planned: features are static crates) |
| **Typed Slint contract** (2026-11-28): screen states are `export enum`s named after their feature (`ShellScreen`, `ShellSection`, `TasksPhase`, `AdminTab`, ...); keys into text tables (error kinds, validation keys, status) stay strings because they are the cross-platform contract keys (`docs/contract/behavior/error-kinds.json`) | Accepted; not compiled | A mistyped state string compiled and rendered a blank area | Slint gains string-enum interop with Rust |
| **Feature glue by `include!`** (2026-11-28): each feature's binding code is `src/ui_glue_body.rs`, included by its `ui_glue.rs` and by the shell with `feature` naming the crate; a feature compiles its own `.slint` only with its default `standalone` feature, the shell depends with `default-features = false` | Accepted; not compiled | The old `build.rs` rewrote source text (`replace("crate::", ..)` after a doc-comment marker) and every view was compiled twice | Slint can compile a library once for several crates |
| **Catalog context per module** (2026-11-28): `packages/i18n` writes `msgctxt "<module>"`, views use `@tr("<module>" => ..)`, the shell's merge keys entries by context and fails on a conflicting duplicate | Accepted; generator and parity checks pass, Rust not compiled | 47 differing translations were silently dropped by "first one wins" | A shared-strings catalog |
| **Sealed local data** (2026-11-28): AES-256-GCM (`aes-gcm`) seals outbox payloads and key-value values; the 32-byte data key is in the OS keychain (`data_key.rs`); without a keychain the key lives for one run (never plaintext, never a file); each value is bound to its row by the GCM associated data (key-value key; outbox id and kind) and there is no plaintext fallback, so a row planted in the file is never delivered; a payload that cannot be opened is parked as `unreadable` | Accepted; not compiled | ADR-0001 promised data at rest encryption that did not exist | SQLCipher or OS-level encryption becomes a requirement |
| **Connectivity by probing the API host** (2026-11-28): a TCP connect to the API host and port (60 s online, 10 s offline) drives `offline` vs `unavailable` and triggers outbox delivery on reconnect; window visibility (minimized or not) pauses the unread poller | Accepted; not compiled | The OS "connected" flag says nothing about the one host the app needs, and the HTTP client uses no proxy | A proxy is supported by the HTTP client |
| **Pagination primitive** (2026-11-28): `aedst_common::PageCursor` (epoch, next token, in-flight flag) is shared by every paged list; a stale page never leaves "load more" stuck | Accepted; not compiled | The same epoch logic was copied five times and four copies had the stuck-flag bug | n/a |
| **Refresh-token rotation is installed in memory before the keychain write** (2026-11-28); a failed write is logged and retried with the next refresh; a sign-out during the write clears the keychain again | Accepted; not compiled | A failed write used to drop the rotated token, and a replayed old token makes a provider with reuse detection revoke the session | n/a |
| Slint UI rules from the official Slint 1.19 and Rust docs ([slint-rules](/desktop/slint-rules)): nothing slow on the UI thread, `ListView` with one long-lived model for long lists, images decoded and downscaled off-thread, explicit renderer, release profile and `windows_subsystem` | Accepted 2026-11-28; in-place list models (`aedst-slint-model`) and off-thread, downscaled viewer images and `ListView` for every paged feature list (features may import exactly `ListView` from `std-widgets.slint`, gates D5 and `check:ui-kit-only`) written the same day without a Rust toolchain (not compiled), together with the release profile, `windows_subsystem`, explicit Slint features, window-first start-up, runtime shutdown timeout and the 60 s healthy mark; only the GPU renderer decision is open | Official guidance; audit found whole-model replacement, non-virtualised lists and UI-thread pixel copies | A Slint bump changes the cited APIs |
| Renderer: GPU renderer (Skia or FemtoVG) chosen explicitly, software renderer kept as fallback; today `slint` default features (FemtoVG + software) are used unchosen | **Pending**: measure binary size, cold start and an image-heavy screen on Windows and Linux | Image, video and animation load needs GPU; Skia is heavier on disk | Before the first release build |
| Slint licence: ship under Royalty-free-2.0 (attribution terms); `deny.toml` allows only that branch | **Pending** owner confirmation | `GPL-3.0-only OR Royalty-free-2.0 OR Software-3.0`; the licence text has not been read | Before the first release build |
| Signed self-update: Ed25519 manifest (authority) + Velopack (transport/installer); stable/beta channels, signed rollback manifests, crash-loop safe mode; release signing tool `aedst-release`. Windows certificate type **not decided** | Accepted; the Velopack path never ran | Server and clients share one trust model | Velopack adds package signing; a certificate is chosen; arm64 is added |
| Observability: Sentry crash reports are consent-gated, default OFF, **no minidump** (a minidump holds memory that cannot be scrubbed, so native crashes are not reported); one PII scrubber for logs, breadcrumbs and events | Accepted | Stricter than web | Legal review changes the crash-report consent basis |
| Dependency versions bumped 2026-11-04: none needed, every `[workspace.dependencies]` entry was already the latest stable on crates.io. `rand_core` stays 0.6.4 (test-only, `rsa` 0.9 requires it); `connectrpc`/`connectrpc-build` pinned exactly | Accepted | Version policy | Next monthly bump |
