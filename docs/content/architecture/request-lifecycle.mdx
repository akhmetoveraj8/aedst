### The interceptor chain, in order

Defined in `apps/server/cmd/server/wire_http.go`; the order is deliberate (cheapest rejection first).

| # | Stage | Rejects with | Why here |
|---|---|---|---|
| 1 | Tracing (otelconnect) | never | Everything after is traced |
| 2 | Error headers and error log | never | Real causes are logged server-side; clients get generic messages |
| 3 | Client-version gate | `FAILED_PRECONDITION` + `CLIENT_UPGRADE_REQUIRED` | Cheapest check, drops unsupported builds ([ADR-0009](/decisions/0009-api-compatibility-and-client-versioning)) |
| 4 | Unauthenticated rate limit | `RESOURCE_EXHAUSTED` | Protects the verifier from floods |
| 5 | Authentication (OIDC) | `UNAUTHENTICATED` | Verifies the JWT, puts the caller in the context |
| 6 | Role policy | `PERMISSION_DENIED` | `AEDST_ROLE_POLICY`, never in handlers |
| 7 | Per-user rate limit | `RESOURCE_EXHAUSTED` + `Retry-After` | Fair share per caller |
| 8 | Protovalidate | `INVALID_ARGUMENT` | Bounds declared in the `.proto` |
| 9 | Idempotency header | never | Makes the key available to the handler |

Panics are recovered into `INTERNAL`. Load shedding (`AEDST_MAX_IN_FLIGHT`) runs before the chain at the HTTP layer.

## Browser path (BFF)

The browser never holds a token. Its calls go to the web app's own `/api/rpc` route, which attaches the access token from an httpOnly cookie, refreshes it when it expires and forwards to the server. This removes CORS and token storage from page JavaScript ([web projects](/web/projects)).

## Retry and conflict semantics

| Situation | Behaviour |
|---|---|
| Same `Idempotency-Key`, same body | First result is replayed; no second write, no second event |
| Same key, different body | `ABORTED` (conflict) |
| `expected_version` is stale | `ABORTED`; re-read and retry |
| Transient failure (`UNAVAILABLE`) | Safe to retry with the same key and backoff |
| Rate limited | `RESOURCE_EXHAUSTED` with `Retry-After` |

Full contract rules: [API design](/engineering/api-design); how to call: [API overview](/api).
