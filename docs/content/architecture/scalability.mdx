# Scalability

Rule: **scale in the cheapest order, and only on a measured trigger.** Operating numbers, metric names and procedures are in the [Scaling guide](/server/scaling); this page is the map.

## Built-in protections

| Protection | Setting | Behaviour |
|---|---|---|
| Load shedding | `AEDST_MAX_IN_FLIGHT` (default 1024) | Excess requests get an immediate `429` with `Retry-After` instead of queueing |
| Per-user rate limit | `AEDST_API_RATE_LIMIT_PER_MINUTE` (default 1200) | Cluster-wide through DragonflyDB; fails open |
| Unauthenticated rate limit | `AEDST_AUTH_RATE_LIMIT_PER_MINUTE` | Per client address on public procedures |
| Bounded pools | `AEDST_DATABASE_MAX_CONNS`, `AEDST_DATABASE_JOBS_MAX_CONNS` | Replicas multiplied by pool size must stay under Postgres capacity; the Helm chart fails the render when it does not fit |
| Keyset pagination | `page_size` capped at 100 | Constant cost per page, no `OFFSET` |
| Retention | One policy per growing table | Append-only tables stay bounded |
| Graceful shutdown | `/readyz` 503, then drain | Rolling deploys drop no requests |

## Connection budget (worked example from the shipped values)

20 API pods x 20 pooled connections = 400 client connections (PgBouncer allows 2000). Jobs pools: (20 + 2) x 10 = 220 direct connections. Pooler server side: 3 x 40 = 120. Reserved for the identity provider: 40. Total 380, under `max_connections` 400. Source and the failure signatures: [Scaling guide](/server/scaling#pooler-sizing-replicas-vs-pgbouncer).

## Known limits

Stated honestly so nobody designs around a feature that does not exist: realtime is a best-effort nudge without resume ([ADR-0021](../../../apps/server/docs/adr/0021-nats-jetstream-and-rust-gateway.md)); the load-test baselines recorded so far are development-machine figures, not capacity numbers; the PgBouncer rehearsal has not yet been run against a live pooler. The authoritative list is [Scaling guide](/server/scaling).
