## Across a database boundary

When a consumer lives in another service with its own database, the producer cannot insert the consumer's job in its own transaction. It inserts a `platform.event_forward` job instead; that job calls `EventIngestService.Deliver` on the consumer's service, which inserts the real delivery in **its** database. Each side keeps its own outbox and retries, and no distributed transaction exists ([ADR-0022](../../../apps/server/docs/adr/0022-event-forwarding-and-service-identity.md), [Event ingest API](/api/events)).

## Event guarantees

| Property | Guarantee |
|---|---|
| Atomicity | Event exists if and only if the state change committed |
| Delivery | At least once; consumers must be idempotent |
| Ordering | Not global; per aggregate use the `version` carried in the payload |
| Loss | Discarded deliveries stay visible for `AEDST_JOBS_DISCARDED_RETENTION_HOURS`; alert on any discard |
| Replay | Projections (search) can be rebuilt by replaying events |
