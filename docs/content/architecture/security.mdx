# Security

The server never stores a password or issues a token. An OIDC provider (ZITADEL by default) authenticates people; the server is a **resource server** that verifies tokens and then authorizes every action ([ADR-0017](../../../apps/server/docs/adr/0017-identity-provider.md), [ADR-0019](../../../apps/server/docs/adr/0019-remove-first-party-auth.md)). Controls and review checklists: [Security standard](/engineering/security).

| Caller | How it is identified | Typical access |
|---|---|---|
| End user | OIDC access token | Own data through public services |
| Staff | Token with the `admin` role (also `support`, `auditor` for reads) | `AdminService`, operator services; every mutation is audited in the same transaction |
| Another service | Machine identity, role `internal` | `EventIngestService`, operator mutations |
| Unauthenticated | none | Only procedures listed as public (`GetCapabilities`) |

## Device and request integrity

Optional attestation proves a request comes from a genuine app: Google Play Integrity ([Integrity API](/api/integrity)) and Apple App Attest ([App Attest API](/api/appattest)). Both use single-use challenges or hashes to prevent replay and report rejection as a normal response, not an error.

## Controls at a glance

| Control | Mechanism |
|---|---|
| Tokens out of page JavaScript | BFF with httpOnly `__Host-` cookie on web |
| CSRF defence in depth | `Connect-Protocol-Version: 1` required on every call |
| Injection | sqlc only; no SQL string building |
| Abuse | Rate limits per address and per user, load shedding |
| Data minimisation in errors | Generic `INTERNAL`; causes only in logs and traces |
| Supply chain | Approved-library allowlists enforced by gates, version pinning, `govulncheck`, gitleaks |
| Audit | `admin.audit_log` written in the effect's transaction |
