## Adding a feature to all clients

Follow the eight-step [client recipe](/client-recipe): declare, domain, data, presentation, navigation, i18n, wire, test. Parity rules are in [Parity](/parity); locales `en`, `ru`, `tg`, `uz`, `ar` must stay in sync ([i18n](/i18n)).

## Compatibility between old clients and new servers

Within `v1` only additive changes are allowed. Clients identify themselves with `X-Aedst-Client: <platform>/<semver>`; below a minimum version the server answers `FAILED_PRECONDITION` with reason `CLIENT_UPGRADE_REQUIRED` and the app shows a forced-upgrade screen. Newly available features are discovered through [`GetCapabilities`](/api/capabilities), not by guessing the server version ([ADR-0009](/decisions/0009-api-compatibility-and-client-versioning)).
