# Resilience

Design rule: **only PostgreSQL is required.** Every other dependency is optional or degrades (the rate limiter to per-replica limits, the cache to direct loads), so a partial outage degrades features instead of stopping the API.

| Dependency | Failure effect | Detection | Recovery |
|---|---|---|---|
| PostgreSQL primary | API unavailable | `/readyz` 503, pool metrics | Failover (CloudNativePG); clients retry with the same key |
| DragonflyDB | Limits not enforced | `/readyz` `degraded` | Restart; no data to recover |
| Identity provider | No new sign-ins; existing tokens verify from cached JWKS | Auth error rate | Restore IdP; one forced JWKS refresh on unknown `kid` |
| Object storage | Media upload and completion fail | Media error rate | Restore storage; abandoned uploads are cleaned by retention |
| NATS / gateway | Realtime delayed | `aedst_events_*` lag, forward job retries | Restore; clients resync through the API |
| Consumer bug | One consumer retries, then discards | `aedst_events_discarded_total` (any increase alerts) | Fix, then replay from the discarded list |

## Patterns used

| Pattern | Where | Effect |
|---|---|---|
| Transactional outbox | `events.Publisher` with River `InsertTx` | No lost or phantom events |
| Idempotency keys | `platform/idempotency`, guarded SQL | Retries and offline queues are safe |
| Optimistic concurrency | `expected_version` | Lost updates become `ABORTED` |
| Timeouts, breaker, per-call rate limit | `platform/resilience` for cross-process calls | A slow unit cannot hold every goroutine |
| Load shedding | `AEDST_MAX_IN_FLIGHT` | Latency does not collapse for everyone |
| Graceful shutdown | `/readyz` 503, drain, stop | Zero-drop rollouts |
| Backoff and discard | River | Poison events become visible, not infinite |
| Offline outbox on clients | Android/Apple/Web queues send the item id as `Idempotency-Key` | User work survives bad networks |

## Health endpoints

`/healthz` says the process is alive; `/readyz` says it can serve (PostgreSQL reachable, not draining). Optional dependencies never appear as failures there. What to do when an alert fires: [Runbook](/server/runbook).
