## TasksService

TasksService is the tasks module's public API boundary (see
docs/content/server/modules.md). It is the reference module for the AEDST pattern: every
RPC here demonstrates the same module shape (domain/application/
infrastructure/transport/api) any future module should follow.

Every RPC operates on the caller's own tasks only. `user_id` is never a
request field — it is derived from the authenticated context
(internal/platform/httpserver's AuthInterceptor), never trusted from the
client. Trusting a client-supplied user id here would be a textbook IDOR
vulnerability; TasksService is deliberately designed so that mistake is
not representable in the request shape at all.

### UpdateTask

Mutates title/description/priority/due_date only — never status. Status
is a state machine (see TaskStatus), not a plain field: it only moves
through CompleteTask/ReopenTask, which is also where completed_at is
stamped/cleared. This keeps "can DONE go back to IN_PROGRESS without an
explicit reopen" a single well-known no, not something every caller of
UpdateTask has to remember not to do by omitting status from the mask.

**Request** `UpdateTaskRequest`

| Field | Type | Constraints | Description |
|---|---|---|---|
| `id` | `string` | UUID | — |
| `title` | `string` | max length 200 | title and priority are validated by the domain only when named in update_mask (or when there is no mask), so a client that updates just due_date need not resend them. |
| `description` | `string` | max length 4000 | — |
| `priority` | [TaskPriority](#taskpriority) | known value | — |
| `due_date` | `google.protobuf.Timestamp` | — | — |
| `update_mask` | `google.protobuf.FieldMask` | — | Which of title/description/priority/due_date to apply — lets a client clear due_date (present in the mask, absent as a value) without also having to resend the current title/description/priority verbatim. |
| `expected_version` | `int32` (optional) | ≥ 1 | Optimistic concurrency: when set, the update applies only if the task is still at this version; otherwise the RPC fails with ABORTED and the client should re-read and retry. Omit for last-write-wins. |

## TasksOperatorService

TasksOperatorService is the cross-owner (operator) surface of tasks. The admin
module calls it when tasks is not hosted in its own process; in a monolith the
same operations run in-process through tasks/api.AdminService and this service
is mounted but unused. It is closed to ordinary users: the module's built-in
role policy admits only "admin" (a human operator whose token the admin module
forwards, for reads), "support"/"auditor" (reads they already have in admin)
and "internal" (the machine identity of the admin.apply job, for mutations).
Mutations are idempotent on idempotency_key.

| RPC | Path | Summary |
|---|---|---|
| [ListAllTasks](#listalltasks) | `/aedst.tasks.v1.TasksOperatorService/ListAllTasks` | Lists tasks across owners, newest first (keyset). |
| [GetAllTaskStats](#getalltaskstats) | `/aedst.tasks.v1.TasksOperatorService/GetAllTaskStats` | Counts over every owner's tasks (capped, see the fields). |
| [OperatorDeleteTask](#operatordeletetask) | `/aedst.tasks.v1.TasksOperatorService/OperatorDeleteTask` | Deletes any user's task and publishes TaskDeleted in the same transaction. |
