# App Attest API

## AppAttestService

AppAttestService verifies Apple App Attest (DeviceCheck) evidence produced by
the Apple apps (iOS/iPadOS; Apple's validation guide: "Validating apps that
connect to your server"). It is the Apple counterpart of IntegrityService.

Flow:
  1. CreateChallenge  -> a single-use server challenge.
  2. (client) DCAppAttestService.generateKey() once per install, then
     attestKey(keyId, clientDataHash = SHA-256(challenge)).
  3. Enroll           -> the server validates the attestation object and
     stores the key. Done once per key.
  4. (client) generateAssertion(keyId, clientDataHash) for each request it
     wants to vouch for.
  5. VerifyAssertion  -> the server verifies the signature and the counter.

Authenticated callers only. Disabled until AEDST_APPATTEST_ENABLED=true
(FAILED_PRECONDITION while disabled). A bad attestation or assertion is NOT
an RPC error: the call succeeds with verified=false and a reason, so the
client can decide what to do (re-enroll, retry, degrade). RPC errors mean
the request itself is wrong (INVALID_ARGUMENT, UNAUTHENTICATED), the caller
is rate limited (RESOURCE_EXHAUSTED) or the server failed (INTERNAL).

Not covered: Apple's receipt / fraud-risk metric (the receipt inside the
attestation is ignored), and per-RPC enforcement (verification is a separate
call, no other RPC requires an assertion yet).

### CreateChallenge

Returns a fresh 32-byte random challenge bound to the calling user.
Single use, valid for 5 minutes, rate limited per user.

**Request** `CreateChallengeRequest`

_No fields._

**Response** `CreateChallengeResponse`

| Field | Type | Constraints | Description |
|---|---|---|---|
| `challenge` | `bytes` | — | 32 random bytes. Use it for exactly one Enroll call: the client computes clientDataHash = SHA-256(challenge) and passes that hash to attestKey. Consumed by the first Enroll that presents it, whether that Enroll succeeds or not; ask for a new one after any failure. |
| `expires_at` | `google.protobuf.Timestamp` | — | The challenge is rejected from this instant on (5 minutes after issue). |

Example:

```bash
curl -sS "$AEDST_URL/aedst.appattest.v1.AppAttestService/CreateChallenge" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Connect-Protocol-Version: 1" \
  -d '{}'
```

Response (`200`):

```json
{
  "challenge": "c2FtcGxl",
  "expiresAt": "2026-11-19T09:30:00Z"
}
```

### Enroll

Validates an attestation object and registers the attested key.

**Request** `EnrollRequest`

| Field | Type | Constraints | Description |
|---|---|---|---|
| `key_id` | `string` | length 44, pattern ^[A-Za-z0-9+/]{43}=$ | The key identifier returned by generateKey(): standard base64 (with padding, 44 characters) of SHA-256 over the uncompressed X9.62 public key. |
| `attestation_object` | `bytes` | min length 1, max length 32768 | The raw bytes returned by attestKey() (a CBOR object, fmt "apple-appattest"). Never logged. |
| `challenge` | `bytes` | length 32 | The challenge from CreateChallenge that attestKey() was bound to (clientDataHash = SHA-256 of exactly these 32 bytes). |
| `bundle_id` | `string` | max length 155, pattern ^([A-Za-z0-9-]+(\\.[A-Za-z0-9-]+)*)?$ | The app's bundle identifier. The server validates the attestation against the App ID "<AEDST_APPATTEST_TEAM_ID>.<bundle_id>", so it must be one of AEDST_APPATTEST_ALLOWED_BUNDLE_IDS. Empty means "the only allowed bundle id" and is rejected (BUNDLE_NOT_ALLOWED) when several are configured. |

**Response** `EnrollResponse`

| Field | Type | Constraints | Description |
|---|---|---|---|
| `verified` | `bool` | — | — |
| `reason` | [FailureReason](#failurereason) | — | — |
| `environment` | [Environment](#environment) | — | Present when verified is true. |

Example:

```bash
curl -sS "$AEDST_URL/aedst.appattest.v1.AppAttestService/Enroll" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Connect-Protocol-Version: 1" \
  -d '{
  "keyId": "0192f3c4-7a1e-7b52-9d3e-4c1f8a6b2e10",
  "attestationObject": "c2FtcGxl",
  "challenge": "c2FtcGxl",
  "bundleId": "0192f3c4-7a1e-7b52-9d3e-4c1f8a6b2e10"

```

Response (`200`):


## Types

### Environment

| Value | Number | Description |
|---|---|---|
| `ENVIRONMENT_UNSPECIFIED` | 0 | — |
| `ENVIRONMENT_PRODUCTION` | 1 | aaguid "appattest" + 7 zero bytes: a distributed (TestFlight / App Store) build. |
| `ENVIRONMENT_DEVELOPMENT` | 2 | aaguid "appattestdevelop": a build run from Xcode. Only accepted when AEDST_APPATTEST_ALLOW_DEVELOPMENT=true (never in staging or production). |

### FailureReason

Why verified is false. UNSPECIFIED when verified is true. Only coarse
categories are exposed on purpose: the detail is in the server log (reason
code only, never the evidence).

| Value | Number | Description |
|---|---|---|
| `FAILURE_REASON_UNSPECIFIED` | 0 | — |
| `FAILURE_REASON_CHALLENGE_INVALID` | 1 | Enroll: the challenge is unknown, expired, already used or issued to another user. Fetch a new one with CreateChallenge. |
| `FAILURE_REASON_BUNDLE_NOT_ALLOWED` | 2 | bundle_id is not in AEDST_APPATTEST_ALLOWED_BUNDLE_IDS (or empty while several are allowed). Enroll and VerifyAssertion. |
| `FAILURE_REASON_ATTESTATION_MALFORMED` | 3 | Enroll: the attestation object is not a well-formed App Attest attestation. |
| `FAILURE_REASON_CERTIFICATE_CHAIN_INVALID` | 4 | Enroll: the certificate chain does not lead to the Apple App Attestation Root CA (or a certificate is outside its validity period). |
| `FAILURE_REASON_NONCE_MISMATCH` | 5 | Enroll: the nonce in the credential certificate is not SHA-256(authData \|\| SHA-256(challenge)) for the supplied challenge. |
| `FAILURE_REASON_KEY_ID_MISMATCH` | 6 | Enroll: key_id is not the hash of the attested public key, or differs from the credentialId in the authenticator data. |
| `FAILURE_REASON_APP_ID_MISMATCH` | 7 | The authenticator data's RP ID hash is not SHA-256("<team id>.<bundle id>"). |
| `FAILURE_REASON_COUNTER_NOT_ZERO` | 8 | Enroll: the attestation counter is not 0. |
| `FAILURE_REASON_AAGUID_INVALID` | 9 | Enroll: the aaguid is neither "appattestdevelop" nor "appattest" + 7 zero bytes. |
| `FAILURE_REASON_ENVIRONMENT_NOT_ALLOWED` | 10 | Enroll: a development-environment key while the server only accepts production. |
| `FAILURE_REASON_KEY_ALREADY_ENROLLED` | 11 | Enroll: this key is already enrolled. Generate a new key and attest again. |
| `FAILURE_REASON_KEY_UNKNOWN` | 12 | VerifyAssertion: the key is not enrolled for this user, or it was revoked or purged. The client discards its stored key and re-enrolls. |
| `FAILURE_REASON_ASSERTION_MALFORMED` | 13 | VerifyAssertion: the assertion object is not a well-formed App Attest assertion. |
| `FAILURE_REASON_SIGNATURE_INVALID` | 14 | VerifyAssertion: the signature does not verify with the enrolled key for this action and payload. |
| `FAILURE_REASON_COUNTER_NOT_INCREASING` | 15 | VerifyAssertion: the assertion counter is not greater than the last accepted one (a replayed assertion, or a cloned key). The same assertion can never verify twice. |
