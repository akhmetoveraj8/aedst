## NotificationsService

NotificationsService serves the caller's in-app inbox and manages the push
channels (Web Push, FCM, APNs) notifications are fanned out to. Like
TasksService, every RPC is scoped to the authenticated caller — user_id is
never a request field.

The inbox is a projection: the notifications module never receives a
synchronous call from the module that caused a notification. It consumes
that module's integration events (reference: tasks.v1.TaskCompleted) inside
an inbox transaction and delivers push messages from a River job.

## NotificationsOperatorService

NotificationsOperatorService is the operator surface of notifications. The
admin module calls it when notifications is not hosted in its own process; in
a monolith the same operations run in-process through
notifications/api.Broadcaster. Closed to ordinary users: the module's built-in
role policy admits "admin" (a human operator whose token is forwarded, for
reads) and "internal" (the machine identity of the admin.apply job, for
mutations). Mutations are idempotent on idempotency_key.
