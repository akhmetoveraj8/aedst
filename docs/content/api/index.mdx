# API overview

The API is **ConnectRPC over HTTP**, defined in Protobuf under `apps/server/api/proto/aedst/<module>/v1/`. It is not REST: there is one `POST` per RPC. The per-module reference pages ([Modules](/modules)) are **generated from the `.proto` files** (`task docs:api`), together with one OpenAPI 3.1 document per package (`/openapi/aedst.<module>.v1.yaml`), so field names, bounds and comments cannot drift from the contract. Design rules: [API design](/engineering/api-design).

### Headers

| Header | Required | Meaning |
|---|---|---|
| `Authorization: Bearer <access token>` | Yes, except public RPCs | OIDC access token from the identity provider |
| `Content-Type: application/json` | Yes | Or `application/proto` for binary Protobuf |
| `Connect-Protocol-Version: 1` | Yes | CSRF defence in depth; calls without it are rejected |
| `Idempotency-Key: <1-128 printable ASCII>` | Recommended on writes | Makes retries safe; scoped per caller |
| `X-Aedst-Client: <platform>/<semver>` | First-party clients | Used for the minimum-version gate and metrics, for example `android/1.4.2` |
| `Connect-Timeout-Ms` | Optional | Per-call deadline |

### JSON mapping

Field names are `lowerCamelCase` (`due_date` becomes `dueDate`), enums are their names, `int64` values are strings, timestamps are RFC 3339, `bytes` are base64. Unknown enum values must be tolerated by clients.

## Examples

<Tabs items={["curl", "TypeScript", "Kotlin", "Swift"]}>
  <Tab value="curl">
```bash
export AEDST_URL=http://localhost:8080
export TOKEN=<access token from your identity provider>

curl -sS "$AEDST_URL/aedst.tasks.v1.TasksService/CreateTask" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Connect-Protocol-Version: 1" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"title":"Write the release notes","priority":"TASK_PRIORITY_HIGH"}'
```
  </Tab>
  <Tab value="TypeScript">
```ts
import { createClient } from "@connectrpc/connect";
import { createConnectTransport } from "@connectrpc/connect-web";
import { TasksService } from "@/shared/api/connect/generated/aedst/tasks/v1/tasks_pb";

// In the browser the base URL is the app's own BFF route; it adds the token.
const client = createClient(TasksService, createConnectTransport({ baseUrl: "/api/rpc" }));
const { task } = await client.createTask({ title: "Write the release notes", priority: 3 });
```
  </Tab>

## Errors

Errors use Connect codes. Over JSON the body is:

```json
{
  "code": "invalid_argument",
  "message": "title: value length must be at least 1 characters",
  "details": []
}
```

| Connect code | HTTP | Meaning and what to do |
|---|---|---|
| `invalid_argument` | 400 | Input violates a bound; fix the request, do not retry |
| `unauthenticated` | 401 | Missing, expired or invalid token; refresh it once, then sign in again |
| `permission_denied` | 403 | Role policy forbids the procedure |
| `not_found` | 404 | Missing, or owned by another user (existence does not leak) |
| `already_exists` | 409 | The resource already exists |
| `aborted` | 409 | Stale `expected_version`, or an `Idempotency-Key` reused with a different body; re-read and retry |
| `failed_precondition` | 400 | State forbids it; with reason `CLIENT_UPGRADE_REQUIRED` the app must update |
| `resource_exhausted` | 429 | Rate limited or load shed; honour `Retry-After` |
| `unavailable` | 503 | Transient; retry with backoff and the same `Idempotency-Key` |
| `internal` | 500 | Generic message only; the cause is in server logs |

## Pagination

Lists use opaque cursors: send `page_size` (server default when 0, capped at 100) and `page_token`; read `next_page_token` (empty means last page). A token is bound to its filters and sort; reusing it with different ones is `invalid_argument`. Never parse or build a token.

```bash
# first page, then the next
curl ... -d '{"pageSize":20}'
curl ... -d '{"pageSize":20,"pageToken":"<next_page_token from the previous response>"}'
```

## Partial updates and concurrency

Updates take an `update_mask` listing the fields to apply, so a client can change one field without resending the others, and an optional `expected_version`. If the stored version differs the call fails with `aborted`.

```bash
curl ... "$AEDST_URL/aedst.tasks.v1.TasksService/UpdateTask" \
  -d '{"id":"<task id>","title":"New title","updateMask":"title","expectedVersion":3}'
```

## Rate limits and load shedding

Authenticated RPCs are limited per user (default 1200 per minute); each instance caps in-flight requests. The server answers `resource_exhausted` with `Retry-After`; clients back off with jitter.

## Versioning

Within `v1` changes are additive only (new fields, RPCs, enum values). A breaking change ships as `v2` beside `v1`. Deprecated items carry `deprecated = true` and a replacement. Clients discover optional features with [`GetCapabilities`](/modules/capabilities/api). Rules: [ADR-0009](/decisions/0009-api-compatibility-and-client-versioning).
