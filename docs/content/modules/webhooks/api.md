## WebhooksService

WebhooksService manages outbound webhooks: the endpoints of third parties that
receive integration events as signed HTTPS POSTs (Standard Webhooks format,
docs/content/api/webhooks.md), and the log of what was delivered to them.

It is an operator surface: every RPC requires the `admin` role by default
(the module's built-in role policy; AEDST_ROLE_POLICY may replace it). The
caller is taken from the token, never from a request field. Every RPC answers
FAILED_PRECONDITION (reason WEBHOOKS_DISABLED) while AEDST_WEBHOOKS_ENABLED is
false. A signing secret is returned exactly twice in an endpoint's life at
most: by CreateEndpoint and by RotateEndpointSecret. No other response
carries it and it cannot be read back.

### CreateEndpoint

Registers an endpoint and returns its signing secret once. Replay-safe with
an Idempotency-Key header: a retry returns the same endpoint and secret.

**Request** `CreateEndpointRequest`

| Field | Type | Constraints | Description |
|---|---|---|---|
| `url` | `string` | URI, min length 1, max length 2048 | Absolute https URL with a host, without credentials or a fragment. The address it resolves to must be public (checked on every delivery). |
| `description` | `string` | max length 500 | Free-form note for operators, at most 500 characters. |
| `event_types` | list of `string` | each: min length 1, max length 128, min 1 items, max 32 items, unique | Event types to subscribe to: 1 to 32 distinct types the server offers to webhooks. An unknown type is INVALID_ARGUMENT. |

**Response** `CreateEndpointResponse`

| Field | Type | Constraints | Description |
|---|---|---|---|
| `endpoint` | [Endpoint](#endpoint) | — | The registered endpoint. |
| `secret` | `string` | — | The signing secret in the Standard Webhooks form "whsec_<base64>". Shown only here: store it now, it cannot be read back. |

Example:

```bash
curl -sS "$AEDST_URL/aedst.webhooks.v1.WebhooksService/CreateEndpoint" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Connect-Protocol-Version: 1" \
  -d '{
  "url": "https://cdn.example.com/m/0192f3c4.png",
  "description": "Draft the changelog and tag v1.4.0",
```

### EndpointStatus

EndpointStatus says whether an endpoint receives deliveries.

| Value | Number | Description |
|---|---|---|
| `ENDPOINT_STATUS_UNSPECIFIED` | 0 | Never a valid value. |
| `ENDPOINT_STATUS_ACTIVE` | 1 | Events are fanned out to the endpoint. |
| `ENDPOINT_STATUS_DISABLED` | 2 | The endpoint receives nothing until EnableEndpoint. |

### EndpointDisabledReason

EndpointDisabledReason says who disabled an endpoint.

| Value | Number | Description |
|---|---|---|
| `ENDPOINT_DISABLED_REASON_UNSPECIFIED` | 0 | The endpoint is active. |
| `ENDPOINT_DISABLED_REASON_OPERATOR` | 1 | An operator called DisableEndpoint. |
| `ENDPOINT_DISABLED_REASON_CONSECUTIVE_FAILURES` | 2 | The server disabled it after too many consecutive failed deliveries (AEDST_WEBHOOKS_DISABLE_AFTER_FAILURES): the dead-letter state. |

### DeliveryStatus

DeliveryStatus is the state of one delivery of one event to one endpoint.

| Value | Number | Description |
|---|---|---|
| `DELIVERY_STATUS_UNSPECIFIED` | 0 | Never a valid value. |
| `DELIVERY_STATUS_PENDING` | 1 | Queued or being retried. |
| `DELIVERY_STATUS_DELIVERED` | 2 | The receiver answered 2xx. |
| `DELIVERY_STATUS_FAILED` | 3 | The receiver rejected the delivery for good (a 4xx other than 408, 425 and 429) or every retry was used up. |
| `DELIVERY_STATUS_CANCELLED` | 4 | Not sent: the endpoint was disabled or deleted, or its URL may not be called. |
