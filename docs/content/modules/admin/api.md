## AdminService

AdminService is a composition layer for operators. It owns no tables of
its own except the audit log; every read goes through other modules' api/
packages (tasks, media, notifications). Every RPC requires the
"admin" role — enforced by httpserver.RoleInterceptor through
AEDST_ROLE_POLICY (default `/aedst.admin.v1.AdminService/*=admin`), never
in handler code — and every mutating RPC writes an audit entry in the same
transaction as its effect.

| RPC | Path | Summary |
|---|---|---|
| [GetOverview](#getoverview) | `/aedst.admin.v1.AdminService/GetOverview` | Operator dashboard counters: tasks, media, push devices and the job queue. |
| [ListTasks](#listtasks) | `/aedst.admin.v1.AdminService/ListTasks` | Any user's tasks — the reference for cross-tenant admin reads. |
| [DeleteTask](#deletetask) | `/aedst.admin.v1.AdminService/DeleteTask` | Deletes any user's task; the reason is written to the audit log in the same transaction as the delete. |
| [BroadcastNotification](#broadcastnotification) | `/aedst.admin.v1.AdminService/BroadcastNotification` | Sends a SYSTEM notification to one user (or everyone when user_id is empty) through the notifications module. |
| [ListAuditLog](#listauditlog) | `/aedst.admin.v1.AdminService/ListAuditLog` | Lists audit entries, newest first (keyset). |
