# Apple i18n

**Generated catalogs.** The String Catalogs of `Features/{Admin,Auth,Media,Notifications,Search,Tasks}` are generated from `packages/i18n` (Xcode layout, keys sorted): never edit them by hand, change the shared JSON and run `node packages/i18n/build.mjs --write-apple`. A module's `apple-local.json` lists the few entries kept hand-written because the shared format cannot express them yet (they are merged into the generated catalog verbatim). `App/Shared` (`AedstAppCore`), `AedstCore` and `AedstDesignSystem` are generated too (shared modules `app`, `error` and `ui`; a key whose name carries a format specifier, such as `dsPage %@`, stays in `apple-local.json`). Nothing here has been compiled: Apple was never built.

Cross-platform rules (locales, per-module ownership, content consistency) are in the [i18n overview](/i18n). This page covers only Apple.

| | |
|---|---|
| Mechanism | Xcode **String Catalog** (`.xcstrings`), one per SwiftPM target |
| Module catalogs | `Features/<Name>/Sources/<Name>Presentation/Resources/Localizable.xcstrings`: one catalog per feature, in the shared Presentation target. View models read it with `bundle: .module`; the two UI targets (`<Name>UIiOS`, `<Name>UIMac`) have no resources and pass `bundle: <Name>Strings.bundle`. Entries are `extractionState: manual`, so Xcode does not prune keys that only a UI target uses |
| Why | Native since Xcode 15 and inside this repo's OS floor; holds every locale in one file per target, with no per-locale `.lproj` folders to keep in sync. |
