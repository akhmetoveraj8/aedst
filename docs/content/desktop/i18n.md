# Desktop i18n

**Generated catalogs.** The `.po` files of every `aedst-*` crate are generated from `packages/i18n` (header `GENERATED`): never edit them by hand, change the shared JSON and run `node packages/i18n/build.mjs --write-desktop`. They are committed because `slint-build` bundles them from the crate; they are catalog data, not generated Rust, so the "no committed generated code" rule does not apply. The msgid is the English text and the msgctxt is the module (`tasks`, `search`, `notifications`, `media`, `admin`, `desktop`), exactly what `@tr("<module>" => "...")` looks up, so changing a shared English text also needs the matching `@tr` string in the `.slint` source. A crate's `desktop-local.json` (module `<name>/desktop-local.json`) lists hand-written entries the shared format cannot express (currently empty). Nothing here has been compiled: no Rust toolchain was available, so the catalogs were checked statically (every `@tr` string has its msgid, `check-i18n-parity`).

Cross-platform rules (locales, per-module ownership, content consistency) are in the [i18n overview](/i18n). This page covers only Desktop.

| | |
|---|---|
| Mechanism | Slint `@tr("<module>" => "text")` with gettext catalogs; `slint-build` bundles the `.po` files and the app switches with `slint::select_bundled_translation` |
| Catalogs | `crates/<crate>/i18n/<lang>/LC_MESSAGES/<crate>.po` for en, ru, tg, uz, ar (the web calls Tajik `tj`) |
| Context | The module (`@tr("tasks" => ...)`), written as `msgctxt` by `packages/i18n`. An explicit context is required: with an empty one Slint would look up `msgctxt` = component name. Until 2026-11-28 the context was empty, and 47 English texts translated differently by two modules were silently overridden in the merged shell catalog (for example the Arabic "Search" of the search screen came from the shell) |
| From Rust | Text from Rust is never translated: pass a key (an error kind) and translate it in `.slint` |
| Shell | `build.rs` of `aedst-desktop` merges the five feature catalogs with the shell's into one catalog per language. Entries are keyed by context, msgid and plural msgid (multi-line, plural and escaped entries are kept verbatim); an identical duplicate is dropped, a different translation of the same key fails the build |
| Parity gate | `tests/catalogs.rs` in each crate fails on a missing, stale, empty or placeholder-changed entry; `task check:i18n` compares keys across platforms |
| Language | `AEDST_LANG` or the OS locale (`sys-locale`) |
| RTL | Arabic only. Slint shapes Arabic and handles bidi, but does not mirror layouts: `AedstLayout.rtl` in `aedst-ui` and explicit `if AedstLayout.rtl` branches in feature views |

Declared exception: `aedst-oidc` stands in for the `auth` module and has no catalogue. It is a UI-free crate (no `.slint`, no `build.rs`), and text from Rust is never translated, so it has nothing to translate: the sign-in screen is drawn by the shell (`crates/aedst-desktop/ui/shell.slint`) and its strings live in `crates/aedst-desktop/i18n/<lang>/LC_MESSAGES/aedst-desktop.po`, covered by the catalogue test of that crate. The strings move with the views if an `aedst-feature-auth` crate is ever created (not planned: sign-in belongs to the identity provider).

Known gaps: counts are not pluralised ("About 1 results"; Slint supports plural forms, the catalogs carry the headers but no plural entries); ru, tg, uz and ar texts are machine-assisted and need native review; a shared-strings catalog would remove the wording differences between features.
