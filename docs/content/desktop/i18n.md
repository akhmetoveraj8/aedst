# Desktop i18n

Cross-platform rules (locales, per-module ownership, content consistency) are in the [i18n overview](/i18n). This page covers only Desktop.

| | |
|---|---|
| Mechanism | Slint `@tr("" => "text")` with gettext catalogs; `slint-build` bundles the `.po` files and the app switches with `slint::select_bundled_translation` |
| Catalogs | `crates/<crate>/i18n/<lang>/LC_MESSAGES/<crate>.po` for en, ru, tg, uz, ar (the web calls Tajik `tj`) |
| Context | The context is EMPTY (`@tr("" => ...)`). Slint otherwise looks up `msgctxt` = component name, and the catalogs carry no `msgctxt` |
| From Rust | Text from Rust is never translated: pass a key (an error kind) and translate it in `.slint` |
| Shell | `build.rs` of `aedst-desktop` merges the five feature catalogs with the shell's into one catalog per language (shell first; the first translation of an identical English text wins) |
| Parity gate | `tests/catalogs.rs` in each crate fails on a missing, stale, empty or placeholder-changed entry; `task check:i18n` compares keys across platforms |
| Language | `AEDST_LANG` or the OS locale (`sys-locale`) |
| RTL | Arabic only. Slint shapes Arabic and handles bidi, but does not mirror layouts: `AedstLayout.rtl` in `aedst-ui` and explicit `if AedstLayout.rtl` branches in feature views |

Known gaps: counts are not pluralised ("About 1 results"; Slint supports plural forms, the catalogs carry the headers but no plural entries); ru, tg, uz and ar texts are machine-assisted and need native review; a shared-strings catalog would remove the wording differences between features.
